# RAG 與微調

> 主要來源為廠商部落格（raw/05），已與論文觀點（raw/04 §6.2）對照。

**口訣**：模型缺「知識」用 RAG，缺「行為」用微調。

| 面向 | RAG | 微調 |
|---|---|---|
| 資料新鮮度 | 更新文件即得新答案 | 凍結於訓練時 |
| 更新成本 | 低（重新索引） | 每次需新訓練與評估 |
| 引用來源 | 可以 | 無 |
| 幻覺 | 較低（以檢索文字為依據） | 對訓練集外的事實不變或更糟 |
| 工程工作 | 索引、檢索調校、prompt 組裝 | 資料整理、訓練、評估、版本管理 |
| 延遲 | 多一步檢索 | 不增加 |

- 可併用：微調管語氣與格式，RAG 管事實
- 論文觀點：RAG 能持續更新知識並控制使用者可存取哪些 chunk；微調的資料烘進模型，基礎模型演進或有新資料時要重做（raw/04）
- 微調仍適合：輸出本身即是產品（嚴格 JSON schema、品牌口吻）
- 微調不能阻止幻覺
